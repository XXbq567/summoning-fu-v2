# 来源与适配边界

官方 hook 是提交事件入口；本地 rollout 核验是**限定版本的兼容层**，不视为稳定公共协议。仅接受精确 CLI 版本 `0.163.0-alpha.10.2`、`0.163.0-alpha.11`；其他版本保守拒绝，不通过 semver 通配自动放行。

## 入场链路

UserPromptSubmit → 有界且静默的 Node hook → 固定产品目录事件文件 → 单实例伴随窗口 → 核验来源 → 约 5 秒后展示。没有对应新根 turn，或者来源仍不一致，会在有界等待后丢弃。该机制不提供 UI 当前选中聊天订阅。

事件标识由 session 与 turn 计算用于去重；本地接收时间不是来源顺序。对应 rollout 必须属于允许的会话目录，session_meta 身份与版本必须匹配，目标必须是最后一个根 task_started，并有有效的来源时间。旧 turn、子 turn、重复提交和迟到消息不能覆盖较新已核验展示。

推理强度只连接 root start 字节位置之后的同 turn context；模型必须匹配当次 hook，effort 使用明确枚举。旧、child、模型不符、冲突、超限或不可解析的候选不能报告可信强度。缺上下文不阻止入场，但保留 unknown。事件自称的推理强度不被信任。

## 本地数据边界

- 事件不保留 prompt 正文，只传有限身份、模型、cwd 与来源路径等核验信息；不会用 prompt 作为标题。
- 标题按同一 session 精确查本地索引，不按索引排序猜当前聊天，也不调用模型补题。
- 固定产品事件目录检查普通文件、大小、过期时间、文件名 hash、打开后身份与物理父目录身份。Windows 本地 drive namespace 与等价应用目录 alias 仅在既有边界内处理，不新增任意可信根。
- 读取有界；不执行 rollout 内容，不读取认证配置来猜中转站或公司。不将源码包或诊断包自动上传。
- metadata 与来源在展示时冻结；生命周期中的 unknown、取消或 Stop 不被解释为成功。当前入口展示时长与工作计时不是同一语义。

字段清洗只是减少误展示风险，不保证用户自定义标题毫无敏感内容。分享截图前仍需自行检查。公开仓库不包含真实 rollout、事件缓存、私人别名或本机采证日志。
